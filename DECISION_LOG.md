# Implementation decisions

- 2026-11-18. The browser reads `VITE_APP_API_BASE` at build time and appends the query, assistant, and CSV routes in one request helper. The base can include a path prefix. Vite no longer proxies API traffic. The API host owns CORS when it runs on a different origin.

- 2026-11-18. Stage 5 keeps ECharts and uses the selected statement's complete ordered row result. The chart suggests a category and prefers typed numeric measures, while letting users choose any category and any plottable measure. Axis titles capitalize the first letter of the selected field. Bar zoom uses a horizontal range slider and a reset button. Pie uses ten theme colors, repeats them in result order, and gives each slice, connector, and tooltip marker the same color. Hover keeps the selected label prominent and fades the other slices, labels, and connectors together. Number formatting, legend placement, and zoom on other chart types remain open.

- 2026-11-18. Stage 4 uses TanStack Query for database lists, object metadata, and Monaco column suggestions. Refresh invalidates those entries together. The CSV picker and autocomplete both consume the same schema list. The object drawer uses Overview, Columns, and DDL tabs and shows the stored creation statement and ClickHouse comments for the selected object.
- 2026-11-18. The activity drawer gives selected details 35% of the body below its header and controls. The list and details scroll independently so long SQL can be inspected while the history remains visible. The selected SQL is formatted for display. Loading it into the editor restores the saved text. The latest 200 outcomes use the new browser storage key, with command messages and unknown write outcomes recorded explicitly. Entries under the previous key are outside the new history.
- 2026-11-18. The editor uses Monaco’s native double-click selection and right-click menu. The menu uses viewport positioning to escape the editor panel’s clipping, with shorter rows and a narrower width. Monaco retains its selection handling and viewport-edge placement.

- SQL autocomplete uses the schema browser’s table list and one read-only column lookup per database on demand. Unqualified table and column suggestions use the current database. Typing a database or table qualifier narrows the suggestions, and Refresh databases replaces the lookup cache. The editor shows table column counts and column owners and types alongside the existing SQL keywords and functions.

- 2026-11-18. Stage 3 sends a raw CSV upload bound to separate database and table identifiers. Express accepts up to 16 MiB per file and keeps at most eight pending uploads in private temporary directories. Verification reads through the header and up to 20 logical records, with one character of lookahead. It uses ClickHouse's CSV parser in a read-only query. Header names match exactly and may be reordered. Explicit defaults and nullable columns may be omitted. Generated columns are excluded from the insert.
- 2026-11-18. CSV confirmation rechecks the table identity and schema, then validates and inserts batches of up to 100 rows and about 256 KiB of CSV. A known validation failure discards the unsent batch. An insert without a reliable acknowledgment stops the import and reports the affected range separately from confirmed rows. Confirmations for one upload share one operation and its result. Uploads expire after 30 minutes. Completed uploads release the file, and the server retains up to 128 receipts for up to 30 minutes. These receipts belong to the running server process.
- 2026-11-18. The CSV modal rechecks changes to the file or destination and ignores responses from replaced selections. It shows verification and the final outcome beside the action. When the browser loses the confirmation response, **Check import result** asks for the same receipt. Progress is shown as an importing state followed by the confirmed row count and any uncertain range.

- 2026-11-18. Stage 2 resolves Run from Monaco’s selection and caret offsets. The keyboard shortcut and popup invoke the same Monaco action. The splitter uses source ranges so caret Run can find a complete statement and an explicitly selected fragment can go to ClickHouse as written. Toolbar Run supplies the whole editor to the existing sequential runner. At a semicolon the caret belongs to the preceding statement. In the gap after it, Run uses the following statement, with trailing whitespace falling back to the last statement.
- 2026-11-18. Stage 2 keeps Monaco’s menu and passes the double-click coordinates to it so Monaco can position it within the viewport. A double-click inside an existing selection preserves it. Otherwise, the menu uses the clicked statement. Express continues to own the per-statement deadline and cancellation.

- 2026-11-18. Stage 1 replaces server pagination and count queries with one completed response per statement. The server reads ClickHouse's compact JSON format incrementally. It keeps column names, types, and positions even when zero rows return. Positional rows also preserve repeated column names. The table pages and resizes locally. Charts receive the full result. The existing Run action can record mixed-script outcomes, stop at a failure, and let users reopen earlier outcomes without execution. Stage 2 owns selection and caret behavior.
- 2026-11-18. Apply the editor's default limit in ClickHouse and ask for one additional row to determine whether to show the 10,000-row notice. Honor explicit outer limits and offsets. Keep the cap outside compound queries and out of writes and sidebar metadata reads. The server standardizes SELECT output formats for the grid and preserves inline INSERT data. A result with eight 650,000-character cells completed against ClickHouse 24.6. Keep the cap row-based for Stage 1.
- 2026-11-18. Express owns the 600-second deadline. It aborts the outgoing request and sends a separate, bounded cancellation request scoped to the generated ClickHouse query ID. A lost write response stays unknown and requires an explicit new run. Insert counts come from ClickHouse's completed response summary. Mutation acknowledgments use completion or submission wording when the affected row count is unavailable.
- 2026-11-18. The browser shows the active statement in a script and uses the timeout outcome returned by Express. A timed-out write tells the user to check the database before retrying. To test it with a two-second deadline, run `CLICKHOUSE_TEST_URL=http://localhost:8123 npm test -- tests/statement-timeout.spec.ts` from the client directory. The test starts a separate Express instance and checks cancellation and write effects in a disposable database.
- 2026-11-18. Run the server integration tests from the project root with `CLICKHOUSE_TEST_URL=http://localhost:8123 npm test`. The tests use uniquely named databases and remove them on completion. The cancellation test checks the live query ID and the ClickHouse cancellation record. The browser tests replace the old server-pagination expectations with observable local navigation, resize, chart, and outcome checks.

- 2026-11-17. Stop now reuses the last transcript when its audio window is unchanged. New audio still finalizes the current window for context; previously committed windows and composer text are not reprocessed. Filtered Whisper's `[BLANK_AUDIO]` marker and its misspelling from worker output. Empty transcription returns quietly without changing existing prompt text. Runtime verification remains deferred.

- 2026-11-17. Changed voice input to continuous PCM capture through an AudioWorklet. The local Whisper worker attempts updated snapshots after each additional second of audio, with one inference at a time and newer snapshots coalesced while inference is busy. Processing windows are bounded internally; recording itself has no duration cutoff. The composer replaces the current voice draft rather than appending overlapping partial results and commits it once on Stop. Stop flushes the capture worklet before final inference. The input is read-only during capture/finalization and scrolls to the latest words. Build passed before the final UI/test additions. Live model latency and microphone behavior remain unverified; the user declined the proposed synthetic test run.

- 2026-11-17. Fixed composer focus after reproducing action selection returning focus to the page body. ClickUI wraps its dropdown trigger in a div, so the nested button was not the element receiving restored focus. The trigger now has a single keyboard-focusable button role. Selecting an action or pressing Escape restores the prompt; outside clicks retain their intended target through a nonmodal menu. Opening the menu avoids anchor movement during width animation. Three focused Playwright regressions pass for selection/Escape, keyboard navigation/voice focus, and one-click outside dismissal. Production build passed. The terminal icon remains for Generate, as requested.

- 2026-11-17. Added local English voice transcription to the floating composer using the user's Whisper worker approach. The worker loads quantized `Xenova/whisper-tiny.en` through pinned Transformers.js 3.8.1 from jsDelivr on first use, with WASM for predictable browser support. Model files are downloaded and cached by Transformers.js; audio is resampled to mono 16kHz and processed in the browser. Recording has no automatic duration cutoff; the user stops it manually, as requested. Transcripts append to the prompt without submitting it. Permission errors, unsupported browsers, worker failures, and closing the composer during setup are handled. Voice controls use ClickUI's `speaker`, `stop`, and `loading-animated` icons because this installed release has no microphone icon. Removed the briefly installed Lucide dependency. No automated tests, microphone capture, or runtime transcription checks were run.

- 2026-11-17. Added an optional compact AI composer below the primary SQL editor. The existing editor/results layout and Run action stay in place. Quick actions select Generate, Fix, Explain, or Improve, and the composer receives the live editor text as context. This is the frontend layout stage; the provider and backend endpoint are still undecided. The UI explicitly indicates that it is not connected and generates no simulated AI answers or SQL edits. Export remains deferred. Tests and runtime checks remain deferred for this change.

- 2026-11-17. Replaced the sidebar column panel with a right-hand table-details drawer opposite the database list. A native modal dialog rendered through a React portal provides focus containment, Escape/backdrop dismissal, and focus restoration. Overview shows the engine, metadata row/storage counts, sorting/primary/partition keys, and comments. Columns includes filtering, full types, defaults, and comments. Create SQL displays the server's stored DDL as text. Statistics are read from `system.tables` without scanning table data, preserving UInt64 values as strings. Loading and retry states cover metadata failures. Automated tests remain deferred.

- 2026-11-17. Added a right-edge sidebar resize handle with pointer capture, left/right keyboard adjustment, Home/End limits, and double-click reset to 260px. Requested width is limited to 220–520px, with a viewport cap to preserve editor space. The existing Monaco and chart resize handling follows the changed layout. No test suite or runtime checks were run for this change.

- 2026-11-17. Diagnosed invisible table details on the running page. Metadata returned 45 columns for `default.trips`, but the `table-column` class collided with Tailwind's display utility, leaving rows at zero height. Renamed it to `schema-column`. After hot reload, rows use grid layout with positive heights and the details panel has a scrollable column list. No automated test suite was run.

- 2026-11-17. Clicking a table opens a sidebar details panel with the qualified table name, engine, columns and types, defaults, and comments. Column metadata loads on demand from `system.columns` using escaped database/table string literals. Switching tables discards stale responses, and closing details leaves the editor unchanged. Tests and runtime verification remain deferred at the user's request.

- 2026-11-17. Added a separate, full-height database sidebar beside the editor workspace, per the user's layout clarification. It reads database names and engines from `system.databases` and table names and engines from `system.tables` through the existing query endpoint. Empty databases remain visible. The reported current database replaces the hard-coded header label. Expanding a database reveals its tables; search and refresh are read-only. On narrow screens the sidebar starts collapsed and opens as an overlay. Metadata errors stay separate from query execution errors. No tests or runtime checks were run, as requested.

- 2026-11-17. Added Table, Bar, Area, Line, and Pie result views using `echarts-for-react`, per the user's library choice. Table is the initial view. Chart columns are selected manually and preserved when switching views. Pie uses the selected X column as category and Y column as value.
- Chart state lives alongside the table view selection. Chart rendering loads on demand with modular ECharts imports. Area uses a line series with an area fill. The React wrapper owns chart initialization, updates, container resizing, and disposal. ClickHouse's exported theme palette controls chart colors, text, and grid lines.
- Charts use all returned rows in their original order, independently of table search and pagination. SQL controls aggregation and sorting. Missing or invalid numbers remain gaps for Cartesian charts and are omitted from Pie. Numeric strings are supported; unsafe integers, booleans, and empty strings are excluded. Pie requires nonnegative values and at least one positive value.
- The user's installation added `echarts-for-react` 3.1.0 and installed its ECharts 6.1.0 peer dependency. Dependency manifests were left to that installation. No tests, build, or browser checks were run for this change, following the user's instruction.

- 2026-11-16. Added a light/dark toggle. Updated dark mode to use the installed ClickHouse UI dark-theme CSS tokens and exported palette for Monaco, replacing the earlier Slack-inspired colors. SQL syntax colors follow ClickHouse CodeBlock dark styling. A single `Theme` union drives the UI provider, document colors, and Monaco, following Model the Domain. The preference is saved in local storage when available. Tests and browser checks remain deferred at the user's request.

- 2026-11-16. The first page follows the supplied editor-over-results reference with a resizable divider, Run action, results table, search, pagination, and execution states. Charts and AI remain later stages.
- Requests use the existing backend contract, `POST /query` with `{ "query": "<editor contents>" }`. Vite forwards `/query` to `http://localhost:8080`. The backend connects to ClickHouse. Production hosting must provide the equivalent routing.
- Monaco is bundled locally with its editor worker and SQL language support. Completion offers SQL keywords and common ClickHouse functions. Schema-aware completion is deferred.
- Query state is a discriminated union covering idle, running, success, and error, following Model the Domain and Type System Discipline. Only one query runs at a time. Displayed elapsed time includes the HTTP request. A 60-second browser timeout does not cancel server execution.
- The initial query uses ClickHouse's built-in `numbers` function and needs no user table. Run sends the entire editor contents. SQL script orchestration is deferred.
- Response rows are validated at the API boundary. Table columns are derived from returned rows. Pagination limits rendered rows, not backend response size.
- Tests and runtime verification are deferred at the user's request. This log lives in the client workspace because the parent decision log is outside the writable workspace.
